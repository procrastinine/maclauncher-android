# Bionic JNI transport

`jni-generate.mjs` uses the existing JNI declaration and call metadata generator. It emits guest entries that forward each call to the host, and the matching host adapters, for every JNIEnv and JavaVM declaration in the selected original `jni.h`. The existing A/V argument decoder, JVM references, exception operations and invocation-resource synchronization stay in the complete shared JNI facade.

The guest table sends one versioned generic host-call packet, containing its generated target, argument storage and original caller PC, through the original Bionic host-module transition. The embedding module calls `klj_bionic_jni_host_call` only after that transition has installed the real host stack and TLS. Generated host targets are checked against the complete generated table before dispatch. Nested calls restore the preceding owner and caller scope. The original caller PC determines FindClass's defining-image loader and the AAPCS64 variadic classification, and executable helpers and dependencies are part of the image graph as well.

`jni-provider.h` publishes an opaque native image identity, the original ELF64 program headers and the image's ABI factory. Only mapped PT_LOAD/PF_X segments identify executable JNI targets, and overlapping independent owners are rejected. Class-loader bindings use the same ranges and keep the original handling of ambiguous loaders. A provisional publication can be aborted before constructors start; image records are retained for the lifetime of the VM. No original handle is cast to another loader's image type.

`klj_jni_invocation_enter_owned` creates a returning provider scope with deferred exit and no setjmp continuation. The provider finishes its original dispatcher and host-import cleanup before leaving that scope. Scoped pre-Attach ownership avoids entering another provider's pthread context. Additional thread-retirement observers run before the shared facade releases its JNIEnv, and they keep the existing legacy lifecycle owner and JVMTI registration.

`klj_bionic_jni_owner` pairs the original guest tables with the shared VM facade. The embedding process supplies the original-thread pre-Attach operation and handles linked-image publication, class-loader binding and constructor ordering, and decides which native entries are accepted. Returned non-JNI tooling interfaces keep their original VM representation. The source component does not choose or activate a runtime.
