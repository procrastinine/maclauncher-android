# Bionic JNI transport

`jni-generate.mjs` uses the existing JNI declaration and call metadata generator. It emits guest carrier entries and host adapters for every JNIEnv and JavaVM declaration in the selected original `jni.h`. The existing A/V argument decoder, JVM references, exception operations and invocation-resource synchronization remain owned by the complete shared JNI facade.

The guest table sends one versioned generic host-call packet containing its generated target, argument storage and original caller PC through the original Bionic host-module transition. The embedding module calls `klj_bionic_jni_host_call` only after that transition has installed the real host stack and TLS. Generated host targets are validated against the complete generated table before dispatch. Nested calls restore the preceding owner/caller scope. The original caller PC supplies FindClass's defining-image loader and AAPCS64 variadic classification; executable helpers and dependencies are part of the image graph too.

`jni-provider.h` publishes an opaque native image identity, original ELF64 program headers and its ABI factory. Only mapped PT_LOAD/PF_X segments identify executable JNI targets. Overlapping independent owners are rejected. Class-loader bindings use those same ranges and retain original ambiguous-loader handling. Provisional publication can be aborted before constructors start; image records are retained for the lifetime of the VM. No original handle is cast to a different loader's image type.

`klj_jni_invocation_enter_owned` creates a returning provider scope with deferred exit and no setjmp continuation. The provider finishes its original dispatcher and host-import cleanup before leaving that scope. Scoped pre-Attach ownership avoids entering another provider's pthread context. Additional thread-retirement observers run before the shared facade releases its JNIEnv; they retain the existing legacy lifecycle owner and JVMTI registration.

`klj_bionic_jni_owner` pairs the original guest tables with the shared VM facade. The embedding process supplies the original-thread pre-Attach operation and owns linked-image publication, class-loader binding, constructor ordering and native-entry admission. Returned non-JNI tooling interfaces retain their original VM representation. The source component does not choose or activate a runtime.
